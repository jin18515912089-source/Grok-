# 初步复盘：认证服务 v3.8 发布导致登录失败（北京时间）

**状态：** 初步。最终根因尚未验证完毕。下文“工作假设”不得视为最终根因。  
**事故窗口：** 14:07–14:49（约 42 分钟错误率显著升高；材料记载事故窗口 47 分钟，自 14:02 发布起算至 14:49 恢复）。  
**严重性：** 生产登录失败；无数据丢失或未授权访问证据。

## 2. 业务影响（与技术现象分开）
- 约 18% 活跃用户至少一次登录失败。
- 1,240 个后台任务失败，均已重放成功。
- 无证据显示数据丢失或未授权访问。
- 变更审批完整。

## 3. 技术现象（已知事实）
- 错误率峰值 11.8%，回滚后 14:37 仍为 1.2%，14:49 回到 0.4%（接近发布前 0.3%，是否完全回到基线待确认）。
- 回滚完成后队列仍积压约 18 分钟。
- 预发布测试通过，但预发布旧格式 token 占比 0.2%，生产约 14%。
- 初步日志显示旧格式 token 路径触发额外 DB 查询，连接池达上限。
- 小流量可以复现。

## 4. 工作假设（非最终根因）
**假设 A（优先）：** v3.8 对旧格式 token 的额外查询在生产高占比（约 14%）下打满连接池，导致登录失败。  
**假设 B（未排除）：** 缓存失效与连接池配置共同作用。  
**假设 C（未排除）：** 其他未记录因素。  
预发布通过只能说明“在旧 token 极低的数据下未暴露”，不能证明代码无缺陷。

## 5. 处置
已做：暂停后续发布；回滚 v3.8；任务重放成功；小流量复现。  
未做：最终根因锁定；连接池/缓存对照实验；对 18% 受影响用户的业务侧说明（未知是否已发）。

## 6. 防复发计划
**48 小时内**
- 冻结认证服务发布，除非回滚验证包。
- 用生产近似的旧 token 占比（约 14%）做回放，分别测试：仅旧 token 路径、仅连接池上限、缓存失效组合（明确接受/拒绝假设 A/B）。
- 核对 14:49 后错误率是否稳定在 ≤0.4%，队列无再积压。

**两周内**
- 预发布数据必须包含与生产同量级的旧格式 token，作为发布门禁。
- 为“额外 DB 查询 / 连接池使用率”加错误预算告警，阈值低于本次打满水平。
- 补齐回滚后队列排空的运行手册。

**长期**
- 旧格式 token 迁移或兼容路径改为常数时间/无额外查询。
- 发布检查单增加“生产数据偏斜”项；定期做预发布 vs 生产数据分布 diff。
