# 认证服务 v3.8 发布事故初步复盘（初步）

**标题说明：** 本报告为“初步”复盘，最终根因尚未完成验证。以下“假设”不得视为最终结论。

## 一、事故概要（事实）

- 事故窗口：**47 分钟**（14:02–14:49，北京时间）。
- 约 **18% 的活跃用户**至少一次登录失败；**1,240 个后台任务失败**，均已重放成功。
- **无证据显示数据丢失或未授权访问**。

## 二、时间线（北京时间，事实）

| 时间 | 事件 |
|---|---|
| 14:02 | 发布认证服务 v3.8 |
| 14:07 | 登录错误率从 0.3% 升至 11.8%，告警触发 |
| 14:12 | 值班工程师确认影响生产，暂停后续发布 |
| 14:18 | 决定回滚 |
| 14:31 | 回滚完成 |
| 14:37 | 错误率降至 1.2%，但异步队列仍积压 |
| 14:49 | 错误率恢复至 0.4%，队列清空，事故结束 |

## 三、业务影响与技术现象（分开表述）

**业务影响：** 登录失败影响约 18% 活跃用户，1,240 个后台任务失败（已全部重放成功）；无数据丢失或未授权访问。

**技术现象：** 初步日志显示，新版本在遇到旧格式 token 时发起额外数据库查询，导致数据库连接池达到上限。小流量复现已成功（17:10）。**尚未排除缓存失效与连接池配置的共同作用**——这是待验证假设，非最终根因。

## 四、已知事实与假设

**已知事实：**
- 版本在预发布环境测试通过，但预发布数据中旧格式 token 占比仅 0.2%，生产约 14%——预发布与生产数据分布存在显著差异。
- 变更审批完整。
- 回滚后错误率恢复，队列清空。

**假设（待验证）：**
1. 假设：旧格式 token 触发的额外查询是连接池耗尽的主要诱因。（部分证据支持，小流量复现成功，但未排除其他因素）
2. 假设：缓存失效与连接池配置共同作用放大了影响。（尚未排除）

## 五、处置（已完成，事实）

回滚 v3.8、暂停后续发布、重放 1,240 个失败任务、清除积压队列。

## 六、防复发计划

**48 小时内：**
1. 完成旧格式 token 触发额外查询的代码级定位。
2. 在预发布环境补充含高占比旧格式 token 的测试数据（当前仅 0.2%，生产 14%）。

**两周内：**
3. 复现并验证缓存失效与连接池配置的相互作用，确定最终根因。
4. 将连接池上限与告警阈值纳入发布前检查清单。

**长期：**
5. 建立发布前“生产数据分布差异”评估机制，预发布数据应更贴近生产分布。
6. 完善连接池容量模型与压测，避免单点耗尽。

**结论：** 本事故已恢复，但根因尚未最终确认，防复发计划需在最终根因确认后更新。
